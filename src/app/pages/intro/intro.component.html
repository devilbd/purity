Core Framework Architecture & Primitives

Code & Primitives

1. 🔄 Fine-Grained Reactive Signals & Effects (core.ts)

Synchronous reactivity primitives with automated dependency tracking and sub-microsecond updates:

import { signal, effect } from '@purity/core';

// 1. Create typed reactive signals
const count = signal<number>(0);
const multiplier = signal<number>(2);

// 2. Read value via getter call
console.log(count()); // 0

// 3. Mutate value with .set() or computed .update()
count.set(10);
count.update(n => n + 1); // 11

// 4. Effects automatically register signal dependencies and re-run on changes
effect(() => {
    const total = count() * multiplier();
    console.log(`Calculated total: ${total} (count: ${count()})`);
});

2. 💉 First-Class Dependency Injection (di.ts)

Singleton service registration with @Injectable and instant token resolution via inject():

import { Injectable, signal, inject, Component } from '@purity/core';

export interface User {
    id: number;
    name: string;
    role: string;
}

// 1. Declare injectable singleton service
@Injectable('DataService')
export class DataService {
    currentUser = signal<User | null>(null);

    login(username: string): User {
        const user: User = { id: Date.now(), name: username, role: 'admin' };
        this.currentUser.set(user);
        return user;
    }

    logout(): void {
        this.currentUser.set(null);
    }
}

// 2. Inject singleton service anywhere by constructor or token
@Component({ selector: 'user-profile' })
export class UserProfileComponent {
    private dataService = inject(DataService);

    onLogout() {
        this.dataService.logout();
    }
}

3. 🌐 HTTP Client Service & Centralized Interceptor Pipeline (http.ts, @interceptors/*)

Full-featured HTTP client with GET, POST, PUT, PATCH, DELETE, and decoupled centralized interceptor classes:

import { Component, inject, HttpClient, type HttpInterceptor, type HttpRequest, type HttpResponse, type HttpNextFn } from '@purity/core';

// 1. Declare centralized interceptor class in src/app/shared/interceptors/
export class AuthInterceptor implements HttpInterceptor {
    async intercept(req: HttpRequest, next: HttpNextFn): Promise<HttpResponse<any>> {
        const authReq = req.clone({
            headers: req.headers.set('Authorization', 'Bearer jwt_token_123'),
        });
        return next(authReq);
    }
}

// 2. Consume HttpClient cleanly inside any page or component
@Component({ selector: 'post-view' })
export class PostViewComponent {
    private http = inject(HttpClient);

    async loadPost() {
        // Automatically flows through all registered interceptors
        const res = await this.http.get<Post>('https://api.example.com/posts/1');
        console.log('Post data:', res.data);
    }
}

6. ⚡ Transform Pipes & Dynamic Parameters (pipe.ts)

Classes decorated with @Pipe transform template values and accept reactive signals as dynamic parameters:

import { Pipe, BasePipe } from '@purity/core';

// 1. Declare transform pipe with typed arguments
@Pipe('myTransformPipe')
export class MyTransformPipe extends BasePipe {
    transform(value: any, isUppercase: boolean = false, prefix?: string): string {
        if (value === null || value === undefined) return '';
        let str = String(value);
        if (isUppercase) str = str.toUpperCase();
        return prefix ? `${prefix}: ${str}` : str;
    }
}

<!-- 2. Use in handlebars with static or dynamic signal parameters -->
<div>{{ myValue() | myTransformPipe: isUppercaseSignal() : '✨ Output' }}</div>
<div>{{ count() | myTransformPipe: true }}</div>

11. 🔍 Child View & Component Queries (@ViewChild)

Property decorator that queries child elements or custom components implicitly by property name, with optional explicit selectors for disambiguation:

import { Component, ViewChild, signal } from '@purity/core';
import type { LoaderComponent } from '@components/loader/loader.component';
import type { CustomComponent } from '@pages/custom/custom.component';

@Component({
    selector: 'demo-component',
    templateUrl: './demo.component.html',
})
export class DemoComponent {
    // 1. IMPLICIT SELECTOR: Automatically infers <loader-component> from property name
    @ViewChild()
    loaderComponent?: LoaderComponent | null;

    // 2. OPTIONAL EXPLICIT SELECTOR: Used when disambiguating multiple instances
    @ViewChild('#component1')
    customComponent1?: CustomComponent | null;

    @ViewChild('#component2')
    customComponent2?: CustomComponent | null;

    onTriggerChild() {
        // Clean property access without manual querySelector boilerplate
        this.loaderComponent?.show('Loading data...');
        this.customComponent1?.customProperty.set('Updated by parent');
    }
}

Framework Lifecycles & Execution Phases

Lifecycles & Phases

21. 🧩 Web Component Lifecycle Phases (@Component)

Native Custom Elements v1 lifecycle flow from template projection and reactive binding to teardown:

import { Component, signal, ViewChild } from '@purity/core';

@Component({
    selector: 'lifecycle-demo',
    templateUrl: './lifecycle-demo.component.html',
})
export class LifecycleDemoComponent {
    private timerId?: number;
    count = signal(0);

    /**
     * PHASE 1: Constructor - Instantiates state & signals.
     */
    constructor() {
        console.log('[1. Constructor] Class instance initialized');
    }

    /**
     * PHASE 2: onInit() - Invoked after connectedCallback():
     * - <slot> content projection resolved
     * - Strict input values sanitized (zero parser warnings)
     * - Template mounted to innerHTML
     * - @ViewChild getters and reactive {{ expressions }} compiled
     * - Directives (@Directive) and Validators (@Validator) attached
     */
    protected onInit(): void {
        console.log('[2. onInit] DOM mounted and all bindings active');
        this.timerId = window.setInterval(() => this.count.update(n => n + 1), 1000);
    }

    /**
     * PHASE 3: onDestroy() - Invoked during disconnectedCallback():
     * - Automatically tears down active Directives (disconnects MutationObservers)
     * - Automatically unbinds active Form Validators
     * - Use for clearing intervals, listeners, and behavior cleanup
     */
    protected onDestroy(): void {
        console.log('[3. onDestroy] Element removed from DOM, cleaning up');
        if (this.timerId) window.clearInterval(this.timerId);
    }
}

22. 🏷️ Custom Directive Lifecycle (@Directive, BaseDirective)

Execution phases for attribute-level reactivity, signal tracking, and host DOM mutation observation:

import { Directive, BaseDirective } from '@purity/core';

@Directive('tooltip')
export class TooltipDirective extends BaseDirective {
    /**
     * PHASE 1: onInit() - Attached to host DOM element:
     * - Access this.element, this.value, this.options
     * - Setup initial classes, attributes, or wrapper spans
     */
    onInit(): void {
        this.element.classList.add('has-tooltip');
        this.onChanges(this.value);
    }

    /**
     * PHASE 2: onChanges(newValue, oldValue) - Reactive signal tracking:
     * - Automatically executed inside an effect() whenever dynamic [tooltip]="textSignal()" changes
     */
    onChanges(newValue: any, oldValue?: any): void {
        this.element.setAttribute('data-tooltip', String(newValue ?? ''));
    }

    /**
     * PHASE 3: onDOMChange(recordOrEvent) - Mutation & Input Observer:
     * - Fires on host element attribute/child mutations or input/change events
     */
    onDOMChange(record: MutationRecord | Event): void {
        // Handle dynamic attribute changes or element resize
    }

    /**
     * PHASE 4: destroy() / onDestroy() - Teardown:
     * - Automatically disconnects MutationObserver and unbinds event listeners
     */
    override onDestroy(): void {
        this.element.classList.remove('has-tooltip');
    }
}

23. 📋 Form Validator Lifecycle & State Pipeline (@Validator)

Decoupled validation pipeline with field binding, live evaluation, CSS state reflection, and submit lock:

     * 3. DOM STATE REFLECTION:
     * - Applies .is-valid / .is-invalid / .is-touched CSS state classes
     * - Automatically enables / disables form submit button
     * 4. TEARDOWN: destroy() automatically unbinds field listeners on unmount
     */
}
